GitEx CTF Pwn — Buffer Overflow Writeup Libc 2 min read · Oct 13, 2025 -- Listen Share Challenge Overview This was a classic stack buffer overflow challenge from GitEx CTF. The binary had basic protections (NX enabled, PIE enabled, no canary) and presented a simple vulnerability in the vuln() function. Initial Analysis When running the binary, it displays: Gift for you: 0x555555555164 [waiting for input] The leaked address helps defeat ASLR/PIE by giving us the base address of the binary. Vulnerability Discovery Analyzing the binary revealed a straightforward buffer overflow: c ssize_t vuln() { void buf;  // 64 bytes allocated on stack return read(0, &buf, 0x96);  // reads 150 bytes - overflow! } The function allocates 64 bytes but allows reading 150 bytes, giving us 86 bytes of overflow. Finding the Offset Used cyclic patterns to determine the exact offset to control RIP: Buffer overflow offset: 72 bytes After 72 bytes of padding, we can control the return address ROP Gadgets Found the necessary ROP gadgets using objdump: pop rax; ret at offset +0x115c pop rdi; ret at offset +0x115e pop rsi; ret at offset +0x1160 pop rdx; ret at offset +0x1162 syscall at offset +0x1159 ret at offset +0x1016 (for stack alignment) Key Discovery The breakthrough came when checking available symbols in the binary: binsh: 0x4028 The binary already contained a binsh symbol pointing to a "/bin/sh" string in memory, eliminating the need to create our own string.
